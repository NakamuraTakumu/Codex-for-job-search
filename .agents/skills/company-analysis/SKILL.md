# 目的

* **用途**: 子オーケストラが会社分析を孫調査エージェントへ委譲するときに使う。

* **孫調査エージェントの出力**: Markdown ではなく YAML を返す。

* **上位の担当**: Markdown への描画、ファイル保存、最終成果物の生成は子オーケストラまたは script が担当する。

* **保存の禁止**: 孫調査エージェントは final artifact を保存・更新・生成してはいけない。子オーケストラが `tmp/company_analysis/runs/<run_id>/subagent_outputs/<uuid>.yaml` 形式の handoff path を明示した場合だけ、返却する YAML と同一内容をその 1 ファイルへ保存してよい。孫調査エージェントは handoff path を生成・変更せず、保存先の決定、Markdown rendering、final artifact の作成は行わない。

* **run\_metadata**: この skill が返す YAML には `run_metadata` を含めない。`run_metadata` は子オーケストラが受理時に追加する。

# 想定読者

* **人物像**: 上位国立大学の研究志向な博士課程学生、またはそれに近いプロフィールの人物を既定とする。

* **居住地**: 仙台を既定とする。

* **関心**: 機械学習、数学や抽象理論、形式化、プログラミング言語理論、ソフトウェア工学、アルゴリズム実装、GPU や型システムのような計算機システム実装、および研究成果をソフトウェアや社会実装へつなぐことにある。

* **優先する評価**: 単なるトピックの一致だけを高く評価せず、博士の専門性が採用制度上どう評価されるかを優先する。

# 中核原則

* **評価対象**: 会社プロフィールとしてではなく、「働く場」として評価する。

* **分離**: 事実と評価を分ける。

* **優先順位**: 速さよりも、評価対象に対する網羅性と、公式 / 非公式の明確な分離を優先する。時間を使ってよく、穴を急いで埋めてはいけない。

* **ローカル汚染の禁止**: リポジトリ内の `document/`、`report/`、archive output、既存の会社分析、review note、他 agent output を読んではいけない。過去のローカル分析を引き継がず、公開情報を直接調べる。

* **出力契約の早期参照禁止**: `references/output-contract.md` を、出力 schema を先に固定するために早い段階で開いてはいけない。最終出力制約を見る前に、まず調査と証拠の骨格を固める。

# 上位オーケストラが渡すデータの読み方

* **固定 scope**: 子オーケストラが渡す `scope` は、この分析で維持する評価対象である。

  * **metadata**: `company_name`、`survey_date`、`slug` は出力の識別情報であり、評価対象を広げる根拠ではない。`slug` が `run_id` 由来の場合も意味的な応募単位名として扱わない。

  * **applicant\_graduation\_cohort**: 応募者の卒業・修了見込み cohort。子オーケストラが `2028卒` のような4桁年表記で渡す。採用年度や `scope.role_family` と混同しない。

  * **scope.user\_label**: ユーザーまたは子オーケストラが指定した表示名。

  * **scope.target\_application\_unit**: 応募者が到達したい採用ルート、職種トラック、または application unit。企業名ではない。

  * **scope.hiring\_entity\_name**: 採用を行う entity の名前。初任給、採用制度、応募経路の確認ではこの entity を優先する。

  * **scope.role\_family**: 職種ファミリー。`researcher`、`research_engineer`、`engineer`、`consultant`、`generalist`、`other` のいずれか。採用年度、卒年 cohort、新卒 / 中途区分ではない。

  * **scope.alternative\_application\_units**: `hiring_entity_name` の entity にある他の採用ルート、職種トラック、または application unit。

  * **scope.workplace\_entity\_name**: 実際に働く場として主に評価する entity の名前。`hiring_entity_name` と違う場合は、その差を保ったまま評価する。

* **近接職種への変更禁止**: 固定 scope に対し、当年採用が未定、停止中、終了済み、または情報不足でも他の職種に置き換えてはいけない。固定 scope のまま、採用導線の弱さや不確実性を記録する。

# Workflow

1. **Scope Check** を行い、得られた固定 scope を使う
2. 評価対象に関係する公式・非公式の情報源を幅広く集める。
3. 重要な曖昧さや欠損がある点については、公式側・非公式側の両方で追加検索する。
4. 証拠は、まず公式 / 非公式で分け、その中で構造化した事実と叙述的な証拠に整理する。
5. 証拠が揃ったら`references/scoring.md` を開き採点を行う
6. `references/output-contract.md` を開き、最終レポートを整形する。
7. 出力準備中に、裏づけのない主張、未解消の矛盾、追加証拠が必要な重要欠損が見つかったら、確定前に調査へ戻る。
8. 返却前に、構造、型、欠損値の扱いを最終点検する。

# Scope Check

* 調査の最初に [references/scope-check.md](references/scope-check.md) を読み、子オーケストラが指定した `scope` が分析可能な応募単位として成立しているか確認する。

* 致命的問題があれば、通常の company-analysis YAML を作らず、`scope_check.verdict: revise_scope` YAML だけを返す。

# 調査方法

## 欠損情報がある場合

* **原則**: 欠損はすぐ未確認扱いにせず、固定 scope に近い情報を追加検索する。

* **fallback 対象**:
  * **職種**: `scope.target_application_unit` が薄い場合は `scope.alternative_application_units`。
  * **企業**: `scope.workplace_entity_name` が薄い場合は `scope.hiring_entity_name`。
  * **年度**: `applicant_graduation_cohort` 向け情報が薄い場合は、直近年度の同一応募単位、同一採用主体、共通制度、または近接職種。
  * **tier**: 公式で埋まらない場合は非公式情報。

* **記録**: fallback 情報を使う場合は、対象との差を `scope.ambiguity_note`、該当 section、または `summary.concerns` に残す。

* **fact_layer**: `official` / `unofficial` は source tier だけで分ける。公式 source 由来の候補値は、年度差、近接職種、共通制度、採用主体差、適用不確実性があっても `fact_layer.official` に入れる。非公式 source 由来の候補値も同じ条件で `fact_layer.unofficial` に入れる。対象との差、不確実性、推定性は本文に残し、候補値が存在しない場合だけ `null` にする。

## 情報源の指針

### 調査対象

* **調査経路**: 公開 web 情報を直接調べる。ローカル既存成果物、過去分析、他 agent output は根拠にしない。

* **職種**: `scope.target_application_unit` を最優先。

* **企業**: `scope.workplace_entity_name` を最優先。

* **応募者 cohort**: `applicant_graduation_cohort` は調査対象者の条件として扱う。`fact_layer` の年度フィルタには使わない。

* **制度・数値 facts**: 固定 scope に対して調査時点で最も新しく、対象に最も近い確認済み情報を優先する。欠損時の fallback は **欠損情報がある場合** に従う。

### 公式情報

* **情報源候補**: 採用ページ、募集要項、FAQ、福利厚生・働き方のページ、会社概要ページ、IR / 有価証券報告関連、研究所・技術組織・技術紹介ページ。

* **必須要件**: 最終 YAML の公式 source は 原則 4 件以上とし、採用情報と、会社情報または IR 情報を含める。公開情報が薄く要件を満たせない場合は、追加調査後に不足原因を `summary.concerns` の `公式source不足:` で始まる項目に明示する。

* **高優先度**:

  * **共通**: 採用ページ、募集要項、FAQ、福利厚生・働き方のページ、会社概要ページ、IR / 有価証券報告関連。

  * **研究職寄り**: 研究所・研究活動の説明ページ。

  * **エンジニア職寄り**: 技術組織・技術紹介ページ、技術説明ページ、事業と技術の接続が見えるページ。

* **注意**: 採用 PR だけに頼ってはいけない。IR、法定開示、研究所ページ、技術論文、事業説明も読み、採用文言と実態を切り分ける。

### 非公式情報

* **情報源候補**: 口コミサイト、選考体験サイト、学生向け就職サイト、個人 blog、個人サイト、CV、研究者 profile、研究室 blog、大学側の再掲募集ページ、イベント告知、発表資料、技術 blog、OSS 活動、GitHub organization などを検索する。

  * **典型例**: `OpenWork`、`キャリコネ`、`エン カイシャの評判`、`OpenMoney`、`ONE CAREER`、`就活会議`、`外資就活`、`note`、`Qiita`、`Zenn`、`はてなブログ`、`GitHub`。

* **必須要件**: **典型例**として挙げた個別サービスは、必ず一度は明示的に検索する。

* **信頼可能情報**:

  * **定義**: 非公式情報のうち、評価対象の判断を直接支えられるだけの信頼可能性を確認できるもの。

  * **満たすべき条件**:

    * **複数系統の支持**: 複数の独立した情報系統で支持されている。同一系統の再掲、転載、ミラー、同じサービス内の別ページ、同じ求人票の別掲載面は 1 系統として扱う。

    * **整合性**: 公式情報や他の信頼可能情報と矛盾しない。矛盾する場合は、矛盾の内容と影響範囲を説明できる。

    * **用途の適合**: 情報源のサービスの目的に沿った内容である。例えば、選考体験サイトの選考プロセスの情報は、会社全体の研究環境の評価には使いにくい。

  * **扱い**: 記録上は非公式情報として分離したまま、評価判断では公式情報と同等の強さ。

* **信頼不可能情報**:

  * **定義**: 信頼可能でないと判断した非公式情報。

  * **扱い**: 信頼不可能と判断した非公式情報は、補助として評価判断に用いる。

* **高優先度**:

  * **共通**: 口コミサイト、選考体験サイト、学生向け就職サイト、個人 blog、個人サイト、CV、研究者 profile、研究室 blog、大学側の再掲募集ページ、イベント告知、発表資料、技術 blog、OSS 活動、GitHub organization など。

  * **研究職寄り**: 個人サイト、CV、研究者 profile、研究室 blog、大学側の再掲、open house や event page、研究 internship reportなど。

  * **エンジニア職寄り**: 技術 blog、OSS、GitHub organization、発表資料、ソフトウェア internship report、engineering staff publication など。

## 先に押さえる数値・制度 facts

* 下記の情報は、公式情報と非公式情報の両方から調査。

* **fallback**: 欠損時の追加調査、年度差の記録、`fact_layer` への反映は **欠損情報がある場合** に従う。

  * **scope.hiring\_entity\_name** を調べる：

    * **初任給**: 月額初任給。

    * **学位別初任給**: 学士・修士・博士の月額初任給。

    * **採用導線**: 採用導線と、職種区分そのものの存在。

    * **到達経路**: 直接応募、親会社経由、グループ会社経由、または不明という到達経路。

  * **scope.workplace\_entity\_name** を調べる：

    * **平均年収**: 平均年収。

    * **新卒3年以内離職率**: 新卒入社者集団の3年以内離職率。

    * **平均勤続年数**: 平均勤続年数。

    * **平均年齢**: 平均年齢。

    * **平均残業**: 月平均残業時間。

    * **年間休日**: 年間休日数。

    * **リモート勤務方針**: リモート勤務方針。

# 評価基準

## 1. phd\_value

* **主判断材料**: 研究実績の制度上の扱い。研究能力や実績を選考で扱う記述。

* **補助材料**: 学位別初任給差、博士向け専用導線、博士の制度上の処遇優位、評価対象に対応する博士応募資格、博士候補を明示的に対象化する採用文言。

* **除外**: 面白そうな仕事内容や研究テーマとの相性、博士卒の給与水準そのもの、研究室規模、R\&D テーマの広さ、具体的な初期配属、研究職の存在そのもの、博士保有者の多さ。

* **高評価例**: 研究の実績や能力が選考や格付けで評価され、学位別初任給差にも研究能力や専門性の差が反映されている。

* **低評価例**: 選考で同調性・順応性を強く評価していたり、博士候補が一般応募者とほぼ同様に扱われること、または博士向け制度 / 評価がほぼ存在しないことを積極的に示している。

## 2. role\_fit

* **主判断材料**: 評価対象に対する公式の採用導線、直接到達可否、親会社 / グループ会社経由か、初期配属、職種別採用か総合職か、専門性と仕事内容の接続、配属確度、募集要項の具体性。

* **補助材料**: 選考体験、職種理解、近接職種の情報。

* **除外**: 会社全体の論文数、研究所全体の外部実績、全社的 R\&D 投資規模、当年採用の open / undecided / delayed そのもの。必要なら不確実性メモに回す。

* **高評価例**: 初期配属と仕事内容が具体的で、専門性との接続が強く、配属確度も高い。

* **低評価例**: 職務や配属候補が広すぎて、専門性が実務でどう生きるか見えにくい。

## 3. rd\_env

* **主判断材料**: 研究所 / R\&D 部門、技術発信、論文、特許、会議、OSS、外部連携、理論と実装の往復を支える環境、それらが固定 target に接続する証拠。

* **補助材料**: 全社的な研究投資や技術資産化の情報。ただし固定 target との接続が弱い場合は補助に留める。

* **除外**: 自分の初期配属確度、job title が research っぽいか、特定 1 つのポジションの魅力。

* **高評価例**: 研究所や R\&D 部門、論文、特許、会議、OSS、外部連携、技術資産化が複数の手がかりで確認できる。

* **低評価例**: 研究基盤が薄い、外部実績が乏しい、継続的な研究 / 技術アウトプットの支えが弱いという具体的な証拠がある。

## 4. compensation

* **主判断材料**: 評価対象に対応する初任給、平均年収、平均残業時間、年間休日、リモート勤務方針。

* **補助材料**: 賞与、福利厚生、住宅支援、勤務地、働き方。

* **除外**: 学位差そのものの評価。

* **高評価例**: 処遇水準が明確に強い、または評価対象固有の給与が一部非公開でも、柔軟な働き方・福利厚生・低〜中程度の負担が総合して強い。

* **低評価例**: 低い給与、重い残業、低い柔軟性、薄い福利厚生、強い勤務地 / 働き方制約の具体的な証拠がある。

## 5. hiring\_process

* **主判断材料**: SPI 等の有無、試験数、online / in person、仙台からの現地面接の負担。

* **補助材料**: 評価対象への到達経路、書類負担、面接回数、選考期間。

* **除外**: 処遇水準そのもの、研究環境の厚み、仕事内容との相性、当年採用の open / undecided / delayed そのもの、仙台から勤務先へ継続的に出社・通勤する想定。研究能力や実績の評価やその負担。

* **高評価例**: 採用負担が軽い、面接や試験が少ない / 効率的、online 対応が良い。

* **低評価例**: generic な就活フィルタが強い、SPI 等に加えて面接や提出物が多い、全体負担が高い。

## 6. stability

* **主判断材料**: 固定された `workplace_entity_name` に対応する会社情報、IR、法定開示、売上、従業員数、資本金、上場有無、親 / グループ支援、事業継続性、新卒3年以内離職率、平均勤続年数、平均年齢。

* **補助材料**: 会社評判、事業見通しに関する追加情報。

* **除外**: 評価対象への到達経路や研究職への配属経路は補助情報としてのみ使う。

* **高評価例**: 売上規模や従業員規模が大きく、上場企業または大手親会社 / グループの支援があり、継続的な事業運営を支える会社情報や IR が複数確認できる。

* **低評価例**: 継続赤字、大きな事業縮小、人員削減、親 / グループ支援の弱さなど、雇用や組織継続への不安を示す具体的な証拠がある。
