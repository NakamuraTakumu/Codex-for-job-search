# 採点の指針

このファイルは、section の `score` を付け始めるとき、または欠損情報、重複した証拠、矛盾する証拠を採点にどう反映するかで迷ったときにだけ読む。

## 基本ルール
- 各 section は `1.0` 〜 `5.0` を `0.1` 刻みで付ける。
- 公式 / 非公式の証拠を分けたうえで、各 section には単一の最終 `score` を付ける。
- 不利な証拠と、単なる欠損情報を区別する。
- 欠損、非公開、当年採用情報の未公表それ自体を理由に `score` を下げてはいけない。不確実性は `scope.ambiguity_note` または `summary.concerns` に記録する。
- `score` は単に材料数や URL 数ではなく、実際に確認できた証拠の信頼性、有利 / 不利の方向、その影響の大きさで決める。
- `5.0`: 直接的で強い肯定材料があり、重要な矛盾や大きな留保がほぼない。
- `4.0`: 肯定材料が十分にあり、全体として明確に有利。一定の留保や間接性があってもよい。
- `3.0`: 肯定・否定が混在する、または間接証拠しかなく強く振れない。
- `2.0`: 明確な不利材料やミスマッチがあり、積極推奨しにくい。
- `1.0`: 直接的な不適合や強い否定材料がある。

## 二重計上の防止
- 同じ証拠、同じ問題点、または同じ不確実性を複数 section で強く数えて、`score` や判断を水増ししてはいけない。
- 当年採用の open / undecided / delayed のような募集状況不確実性は、原則として `scope.ambiguity_note` または `summary.concerns` に 1 回記録し、`role_fit` と `hiring_process` の両方で大きな negative として数えてはいけない。
- 同じ内容の証拠は URL 数ではなく独立した情報の系統で数える。repost や mirror は重みを増やさない。
- 従業員口コミサイトは、同じ系統のものを 1 系統として扱う。

## 証拠の扱い
### 公式情報がない場合
- 公式情報の欠如や公開確認不能それ自体は、強い negative ではない。
- 公式情報が薄い点についても、関連する証拠があれば暫定的な `score` を付けてよい。ただし、不確実性は `scope.ambiguity_note` や `summary.concerns` に残し、欠損だけで強く下げない。

### source tier
- 公式 / 非公式の区分だけで `score` を機械的に上げ下げしてはいけない。
- 各証拠は、直接支える主張、独立性、観測範囲、時期、他証拠との矛盾の有無で扱う。

### 証拠が食い違う場合
- 証拠同士が食い違う場合は、食い違いの内容と影響範囲を `evaluation` または `summary.concerns` に明記する。
- 単一の証拠だけで、より直接的で安定した証拠を覆してはいけない。同方向の独立した系統が複数ある場合は、判断修正の材料として扱ってよい。

## 集計
- 総合点と補正後総合点は、親エージェントまたは Python script が計算する。
- weighted aggregation の正本は Python 実装である。
