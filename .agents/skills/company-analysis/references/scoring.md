# 採点の指針

このファイルは、section の `score` を付け始めるとき、または欠損情報、非公式情報、重複した証拠、矛盾する証拠を採点にどう反映するかで迷ったときにだけ読む。

## 基本ルール
- 各 section は `1.0` 〜 `5.0` を `0.1` 刻みで付ける。
- 公式 / 非公式の証拠を分けたうえで、各 section には単一の最終 `score` を付ける。
- 非公式情報の扱いは `../SKILL.md` の **非公式情報** 節を正本とする。
  - 信頼可能と判断できる非公式情報は、採点上も公式情報と同等の強さで扱ってよい。
- 不利な証拠と、単なる欠損情報を区別する。
  - **補完的推定**をscoreに反映させて良いが、影響は信頼可能でない非公式情報と同等。
  - 欠損、非公開、当年採用情報の未公表それ自体を理由に `score` を下げてはいけない。不確実性は `scope.ambiguity_note` または `summary.concerns` に記録する。
- `score` は単に材料数や URL 数ではなく、実際に確認できた証拠の信頼性、有利 / 不利の方向、その影響の大きさで決める。
- `5.0`: 直接的で強い肯定材料が公式情報または信頼可能情報にあり、重要な矛盾や大きな留保がほぼない。
- `4.0`: 肯定材料が十分にあり、全体として明確に有利。一定の留保や間接性、補完的推定があってもよい。
- `3.0`: 肯定・否定が混在する、または間接証拠しかなく強く振れない。
- `2.0`: 明確な不利材料やミスマッチがあり、積極推奨しにくい。
- `1.0`: 直接的な不適合や強い否定材料がある。

## 補完的推定
公式・非公式を探しても直接情報がない場合は、近接職種、同じ採用主体の共通制度、親会社 / グループ制度、業界水準などから留保付きで推定してよい。

## 二重計上の防止
- 同じ評価点、同じ問題点、または同じ不確実性を複数 section で強く数えて、`score` や判断を水増ししてはいけない。
- 当年採用の open / undecided / delayed のような募集状況不確実性は、原則として `scope.ambiguity_note` または `summary.concerns` に 1 回記録し、スコアには反映しない。

## 集計
- 総合点と補正後総合点は、親エージェントまたは Python script が計算する。
- weighted aggregation の正本は Python 実装である。
